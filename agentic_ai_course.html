Part A

The ideas

No code here. Just simple ideas and examples from daily life.

A1

Why do we need agents?

You will learn: what a normal AI chatbot cannot do.

A language model (like ChatGPT or Gemini) is very good with words. But think of it like a very clever friend locked in a room with no phone and no computer. You can ask questions through the door, and they answer. That's all.

Problem 1

It cannot see your data

Ask "How many jars do we have?" It does not know. It has never seen your stock sheet.

Problem 2

It cannot do things

It can say "Order 600 jars", but it cannot actually place the order.

Problem 3

It answers in one go

Real work needs many steps: check stock, then check suppliers, then compare prices. One answer is not enough.

Problem 4

It can be wrong and sound sure

It may make up a number or a rule. Nobody checks its work.

An agent fixes this. We give our clever friend a phone (tools to look things up and do things), a notebook (memory), time to work step by step (a loop), and a manager who checks the work (rules and approval).

Chatbot, workflow, agent: what is the difference?

ChatbotWorkflowAgent
In simple wordsAnswers a questionFollows fixed steps that a programmer wroteDecides its own next step
Uses tools?NoYes, always the same ones in the same orderYes, it chooses which one
Daily-life exampleAsking a friend "What is GST?"A washing machine: same cycle every timeA good employee: "Supplier is late? Let me check stock, call other suppliers, then tell you."
Think about itA supplier tells you: "Your motors will arrive 14 days late." What would you check before deciding what to do? Write down your list. An agent needs to do exactly the same checks.
A2

What is an AI agent?

You will learn: a simple definition and the 5 parts of every agent.
Simple definitionAn AI agent is a program that is given a goal. It uses an AI model to decide what to do next, uses tools to do it, looks at the result, and keeps going until the goal is reached.

Think of an agent as a new employee in your company:

Agent = Brain + Hands + Memory + Loop + Rules
Brain

The AI model

Understands the question and decides: "What do I need? What should I do?"

Hands

Tools

Small Python functions: read the stock sheet, search a PDF, place an order.

Memory

Notes

What happened so far in this job, and what the company already knows.

Loop

Step by step

Think → do → look at the result → think again. Like a person solving a problem.

Rules

Checks

Company rules and a manager's "yes" before anything important happens.

Goal

The job

Something clear, like "Tell me if we should reorder jars."

How much freedom should we give it?

Same as a new employee: you don't give a trainee the company bank card on day one.

L0

Only talks. Answers questions. No tools. (A chatbot.)

L1

Can look things up. Can read data and documents, but cannot change anything.

L2

Can suggest actions. "I think we should order 600 jars." Code checks it, a person says yes, then it happens. Our project works at this level.

L3

Can do small things alone. Small safe actions happen automatically; big ones still need a person.

L4

Does everything alone. Risky for anything involving money or customers.

A3

The agent loop

You will learn: the steps an agent goes through, using one real question.

Click through each step. The question is: "Should we reorder Jars?"

Look at who does each stepThe AI model does the thinking (plan, decide). Normal Python code does the work (fetch data, do maths, check rules). A person gives the final "yes". Each one does what it is best at.
A4

Plan, Act, Decide

You will learn: the three main moves of every agent, with an easy example.

Think about cooking dinner:

1 · Plan

What do I need?

"To make dal I need dal, onion, tomato, spices. Let me check the kitchen."

2 · Act

Do the steps

Open the fridge, check the shelf, buy what is missing, cook.

3 · Decide

What now?

Taste it. "Needs salt" → act again. "Tastes good" → serve. Done.

An agent does the same. Now the business version:

1. Plan: "What do I need to know?"

The agent makes a list of what to look up. A good trick: give it a menu. Just like a restaurant, the agent can only order what is on the menu. It cannot invent new dishes.

❌ No menu (risky)

"Write any database command you like." It might write something wrong, or even delete data.

✅ With a menu (safe)

"You can ask for: stock, suppliers, prices. Which ones do you need?" It can only pick from the list.

2. Act: "Do it"

Python code does what the plan asked. There are two kinds of actions:

KindExampleIs it risky?Who may do it
Read (look)Check stock, read a policyNo, nothing changesThe agent can do it freely
Write (change)Change a price, place an orderYes, it changes real thingsAgent suggests → code checks → person approves

3. Decide: "What is the answer?"

The model reads everything that was found and gives an answer. It may also suggest one action. Two simple habits make the decision trustworthy:

  • Answer only from the facts we found, not from guesswork.
  • Let code redo the maths. AI models are good with words but can make maths mistakes. A calculator never does.
Things that can go wrong (and the simple fix)
  • Asks for a tool that doesn't exist → only allow tools from the menu.
  • Keeps going round and round → stop after a fixed number of steps.
  • Says "300 ÷ 30 = 15" → code does the maths again.
  • Places the same order twice → remember what was already done.
A5

Tools, memory and knowledge

You will learn: how an agent gets information.

Tools = apps on a phone

A tool is just a normal Python function with a short description. We tell the model: "Here are your tools." The model answers with the name of the tool it wants. Our code runs that function and gives the result back. The model itself never runs anything.

what we tell the model, and what it answers
We say:    "Your tools: get_stock(name), calculator(sum)"
Model says: {"tool": "get_stock", "args": {"name": "jar"}}
Our code:   runs get_stock("jar")  ->  240 jars

Memory = a sticky note and a diary

Short-term

Sticky note

What happened in this task: the question, the tool results. Thrown away when the task is over.

Long-term

Diary

Things that stay: the company database, documents, past decisions.

Three places to find knowledge

1

Database

Like an Excel sheet. Exact numbers: stock, prices, costs.

Question: "How many jars do we have?"

2

Documents (RAG)

Like a library with a helpful librarian. You ask a question, the librarian brings the 2 most useful pages.

Question: "What does our policy say?"

3

Knowledge graph

Like a family tree. Shows who is connected to whom.

Question: "If Apex is late, which products are hit?"

RAG, step by step

RAG means Retrieval-Augmented Generation. In simple words: first find the right pages, then let the AI answer using those pages.

  1. Cut all documents into small pieces (like cutting a book into paragraphs).
  2. Turn each piece into a list of numbers so the computer can compare them.
  3. When a question comes, find the pieces that are most similar to it.
  4. Give those pieces to the AI together with the question.

Knowledge graph, in a picture

things and arrows
Mixer Grinder ──USES──▶ Motor ──SUPPLIED_BY──▶ Apex Motors
Hand Blender  ──USES──▶ Motor
Zenith Mixer Pro ──COMPETES_WITH──▶ Mixer Grinder

"Apex Motors is late. Who is affected?" Follow the arrows backwards: Apex Motors → Motor → Mixer Grinder and Hand Blender. Both products are at risk.

A6

Agent patterns (common ways to build an agent)

You will learn: six common designs, each with a simple example from daily life.

A pattern is just a well-known way of doing something. Like recipes: there are a few basic ones, and most dishes use one of them.

1. ReAct: think, do, look, repeat

In simple wordsThe agent does one small step at a time. After each step it looks at the result and thinks about the next step.
Daily lifeA detective. "Let me check the door... it was locked. So let me check the window... it is broken. So the thief came through the window."
Agent example
Think: I need jar stock.        Do: get_stock("jar")  → 240
Think: I need days left.        Do: divide(240, 20)   → 12
Think: I have the answer.       Answer: "12 days of jars left."
Good forOpen questions where you don't know the steps in advance. You build this in Lab 4.

2. Plan first, then do

In simple wordsThe agent makes the full list first, then does everything on the list, then answers.
Daily lifeA shopping list. You write everything down at home, go to the shop once, buy it all, come back.
Agent example
Plan: I need [jar stock, jar suppliers, purchase policy]
Do:   fetch all three
Answer: "Order 600 jars from ClearJar."
Good forBusiness questions. Fewer AI calls, easier to check. Our project uses this.

3. Checker: someone checks the work

In simple wordsAfter the agent gives an answer, a second step checks it before it is used.
Daily lifeA teacher checking homework. The student writes the answer; the teacher checks the sums.
Agent example
AI says:    "Order 600 jars"
Code checks: stock after order = 42 days  ✓   cost = Rs 36,000  ✓
Result:     PASS
Good forAnything with numbers or rules. Our project checks with code, which never makes maths mistakes.

4. Router: send the question to the right place

In simple wordsFirst decide what kind of question it is, then send it to the right helper.
Daily lifeThe reception desk at a hospital. "Fever? Go to room 3. Broken arm? Go to room 7."
Agent example
"What price for the mixer?"  → pricing helper
"Should we order jars?"      → purchase helper
"What is our policy?"        → document search
Good forWhen there are many different kinds of questions.

5. Team of agents (multi-agent)

In simple wordsSeveral agents, each with one job, working together.
Daily lifeA restaurant: the waiter takes the order, the cook cooks, the cashier takes payment.
Agent example
Decision agent: answers questions and suggests actions
Learning agent: reads new documents and learns new facts
Good forBig systems with different jobs. Our project has these two agents.

6. Human in the loop: ask a person before acting

In simple wordsBefore doing anything important, the agent stops and asks a person.
Daily lifeYour bank asks for an OTP before sending money. A big cheque needs the manager's signature.
Agent example
Agent: "Order 900 motors for Rs 2,97,000. This needs a manager."
Manager clicks Approve → order is saved.
Good forAnything that spends money, changes prices or talks to customers. Our project uses this.
Which one should I use?Start with the simplest one that works. Most real systems mix two or three. Our project mixes Plan first + Checker + Human in the loop + Team of agents.
A7

Keeping agents safe

You will learn: simple rules that make an agent safe to use in a real company.
The AI suggests · the code checks · a person approves

Think of a shop: a new salesperson can suggest a discount, the billing machine checks the maths, and the owner approves big discounts.

Safety ruleIn simple wordsExample
MenusThe AI can only choose from a fixed listIt can ask for "stock", but cannot write its own database command
Check the valuesMake sure numbers really are numbers"three hundred" is rejected; 300 is accepted
Redo the mathsCode calculates again from real dataProfit and stock days are calculated by Python, not by the AI
Rules in codeCompany rules are written in Pythonif margin < 20%: not allowed, the AI cannot argue with it
Levels of approvalSmall things OK, big things need a managerOrder above Rs 2,50,000 → manager must approve
Do it only onceRemember what was already doneClicking "Approve" twice does not create two orders
Step limitStop if the agent goes round and roundMaximum 5 steps
Documents are information, not ordersA document cannot tell the agent what to doA PDF saying "ignore the rules" changes nothing, because rules are in code

Cell 1 · load the model
# Install the Hugging Face library (the "!" runs a command, not Python)
!pip -q install -U transformers accelerate

from transformers import pipeline

# Download a small, free AI model and get it ready
model = pipeline(
    "text-generation",                    # we want the model to write text
    model="Qwen/Qwen2.5-1.5B-Instruct",   # the model's name on Hugging Face
    device_map="auto",                    # use the GPU if we have one
    torch_dtype="auto",
)

# A helper: send a list of messages, get the model's reply back as text
def chat(messages):
    result = model(messages, max_new_tokens=300, do_sample=False)
    return result[0]["generated_text"][-1]["content"]   # the last message = the reply

# An even simpler helper: ask one question, get one answer
def ask(question):
    return chat([{"role": "user", "content": question}])

print("Model is ready!")

Lab 2

Get answers as data (JSON)

Idea: if the model answers in a fixed format, our Python code can read the answer and use it.

JSON is a simple format for data. It looks like a Python dictionary: {"name": "jar", "count": 240}. If the model replies in JSON, Python can turn it into a dictionary.

Cell 4 · a helper to read JSON
import json, re

# Small models sometimes add extra words around the JSON.
# This helper finds the {...} part and turns it into a Python dictionary.
def to_dict(text):
    found = re.search(r"\{.*\}", text, re.S)   # find text between { and }
    if found is None:
        return None                            # no JSON found
    try:
        return json.loads(found.group(0))      # JSON text -> Python dict
    except Exception:
        return None                            # it looked like JSON but was broken
Cell 5 · read an email and get data out
email = "Hello, all Motor deliveries from Apex Motors will be 14 days late. Sorry!"

# We tell the model EXACTLY which shape we want back
reply = ask(f"""Read this email and reply with JSON only, like this:
{{"supplier": "...", "part": "...", "days_late": 0}}

Email: {email}""")

data = to_dict(reply)          # text -> dictionary
print(data)
print("Days late + 1 =", data["days_late"] + 1)   # it is a real number now, we can do maths
{'supplier': 'Apex Motors', 'part': 'Motor', 'days_late': 14} Days late + 1 = 15
What happened?
  • We showed the model the shape of the answer we wanted.
  • The model filled in the values.
  • to_dict turned the text into a dictionary, so Python can use data["days_late"] like any number.
  • This is the bridge between AI and code. Every agent uses it.
Lab 3

Give the model a tool

Idea: the model chooses a tool, our code runs it. (Part A5)
Cell 6 · one tool and a menu
# Our tiny "database": stock and how many we use per day
STOCK = {
    "jar":   {"stock": 240, "daily_use": 20},
    "motor": {"stock": 300, "daily_use": 30},
}

# A tool is just a normal Python function
def get_stock(name):
    return STOCK.get(name, "not found")

# The menu of tools the model is allowed to use
TOOLS = {"get_stock": get_stock}
Cell 7 · the model picks, the code runs
question = "How many motors do we have?"

# 1. Tell the model about the tool and ask which one it wants
reply = ask(f"""You have one tool: get_stock(name). Names are: jar, motor.
Question: {question}
Reply with JSON only: {{"tool": "get_stock", "name": "..."}}""")
choice = to_dict(reply)
print("Model wants:", choice)

# 2. Our code checks the tool is on the menu, then runs it
if choice and choice.get("tool") in TOOLS:
    result = TOOLS[choice["tool"]](choice["name"])
    print("Tool result:", result)
else:
    print("Not allowed")
Model wants: {'tool': 'get_stock', 'name': 'motor'} Tool result: {'stock': 300, 'daily_use': 30}
What happened?
  1. The model did not know the stock. It only said which tool to use.
  2. Our code checked: "Is this tool on the menu?" Yes.
  3. Our code ran the function and got the real number.
If the model asked for a tool called delete_everything, the code would say "Not allowed". That is the menu safety rule.
Lab 4

The loop: our first real agent

Idea: think → do → look → repeat, until the job is done. (Part A3, the ReAct pattern)

Now we add a second tool (divide) and let the model use tools again and again until it has the answer.

Cell 8 · add a divide tool
# A second tool. Models can make maths mistakes, so code does the maths.
def divide(a, b):
    return round(a / b, 1)

TOOLS = {"get_stock": get_stock, "divide": divide}
Cell 9 · the agent loop
INSTRUCTIONS = """Solve the task step by step using tools.
Tools:
- get_stock: needs {"name": "jar" or "motor"}
- divide:    needs {"a": number, "b": number}
Reply with ONE JSON object each time:
- To use a tool:   {"tool": "tool name", "args": {...}}
- When finished:   {"final": "your answer"}"""

def agent(task, max_steps=5):
    # The conversation so far = the agent's short-term memory (sticky note)
    messages = [{"role": "system", "content": INSTRUCTIONS},
                {"role": "user",   "content": task}]

    for step in range(1, max_steps + 1):          # LOOP, with a safety limit
        reply = chat(messages)                    # THINK: model decides the next step
        messages.append({"role": "assistant", "content": reply})
        data = to_dict(reply)

        if data is None:                          # bad answer: ask again
            messages.append({"role": "user", "content": "Please reply with JSON only."})
            continue

        if "final" in data:                       # DECIDE: the model says it is done
            return data["final"]

        tool = TOOLS.get(data.get("tool"))        # only tools from the menu
        if tool is None:
            result = "unknown tool"
        else:
            result = tool(**data.get("args", {})) # ACT: our code runs the tool
        print(f"Step {step}: {data.get('tool')} {data.get('args')} -> {result}")

        # OBSERVE: give the result back to the model, then loop again
        messages.append({"role": "user", "content": f"Result: {result}"})

    return "Stopped: too many steps."

print("Answer:", agent("How many days will our jar stock last?"))
Step 1: get_stock {'name': 'jar'} -> {'stock': 240, 'daily_use': 20} Step 2: divide {'a': 240, 'b': 20} -> 12.0 Answer: Our jar stock will last about 12 days.
What happened?
  1. Step 1: the model thought "I need the jar numbers" and used get_stock.
  2. It got back 240 and 20. We added that result to the conversation.
  3. Step 2: the model thought "now divide 240 by 20" and used divide. It got 12.
  4. Step 3: it had enough, so it replied with "final". The loop stopped.
Nobody told the agent the steps. It decided them itself. That is what makes it an agent.
Try it
  • Ask: agent("Which will run out first, jars or motors?"). How many steps does it take?
  • Run with max_steps=1. What happens? Why is a limit useful?
Lab 5

Search documents (mini RAG)

Idea: first find the right piece of text, then let the model answer from it. (Part A5)

We use TF-IDF to compare texts. In simple words, it gives each text a score based on the important words in it. Texts that share important words get a high match. (Our main project uses exactly this.)

Cell 10 · our "documents" and a search function
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.metrics.pairwise import cosine_similarity

# Our "library": 4 small pieces of company policy
pieces = [
    "Profit margin of any product must never go below 20 percent.",
    "A price cut of more than 10 percent needs a manager's approval.",
    "Every part must have at least 15 days of stock.",
    "Orders above Rs 250000 need a manager's approval.",
]

# Turn every piece into numbers (a "vector")
vectorizer = TfidfVectorizer(stop_words="english")   # ignore words like "the", "of"
vectors = vectorizer.fit_transform(pieces)

# Find the piece that best matches the question
def search(question):
    q = vectorizer.transform([question])             # question -> numbers
    scores = cosine_similarity(q, vectors)[0]        # how similar is each piece? (0 to 1)
    best = scores.argmax()                           # position of the best match
    return pieces[best]

print(search("Can we cut the price by 15 percent?"))
A price cut of more than 10 percent needs a manager's approval.
Cell 11 · answer using the found piece
question = "Can we cut the price by 15 percent?"
found = search(question)                             # 1. find the right policy

# 2. give the policy to the model and ask it to answer ONLY from it
print(ask(f"""Answer using ONLY this policy. If it does not say, answer "I don't know".
Policy: {found}
Question: {question}"""))
Yes, but it needs a manager's approval because it is more than 10 percent.
What happened?
  1. Retrieve: the search found the right policy line (like the librarian finding the right page).
  2. Generate: the model answered using that line, not from guesswork.
That's RAG: find first, then answer.

A small knowledge graph

import networkx as nx

graph = nx.DiGraph()     # a graph where arrows have a direction

# Add arrows:  from --link--> to
graph.add_edge("Mixer Grinder", "Motor",       link="USES")
graph.add_edge("Hand Blender",  "Motor",       link="USES")

# Print every arrow that touches "Motor"
for a, b, info in graph.in_edges("Motor", data=True):

for a, b, info in graph.out_edges("Motor", data=True):

Affected if Apex is late: {'Motor', 'Mixer Grinder', 'Hand Blender'} Mixer Grinder --USES--> Motor Hand Blender --USES--> Motor Motor --SUPPLIED_BY--> Apex Motors
What happened?
  • We stored facts as arrows between things.
  • nx.ancestors followed the arrows backwards and found everything connected to Apex Motors.
  • A database or a text search would not easily answer "who is affected?". A graph does it in one line.
Lab 7

Mini decision agent

Idea: put it all together: Plan → Fetch → Decide → Check → Approve. This is a tiny version of the main project, so the project will feel easy after this.

Step 1 · Company data and a menu

Cell 13 · data
# Our company data (in the real project this lives in a database)
JAR = {"stock": 240, "daily_use": 20}
SUPPLIERS = {
    "ClearJar": {"price": 60, "days_to_deliver": 5},
    "Bharat":   {"price": 66, "days_to_deliver": 7},
}

# The menu: things the AI is allowed to look at
MENU = {
    "jar_stock": JAR,
    "suppliers": SUPPLIERS,
}

Step 2 · Plan (AI) and Fetch (code)

Cell 14 · plan and fetch
# PLAN: the AI says what it needs, picking only from the menu
def plan(question):
    reply = ask(f"""Question: {question}
You may look at: {list(MENU)}
Which do you need? Reply JSON only: {{"need": ["..."]}}""")
    return to_dict(reply) or {"need": []}

# FETCH: our code gets the data. Anything not on the menu is ignored.
def fetch(needs):
    facts = {}
    for name in needs["need"]:
        if name in MENU:
            facts[name] = MENU[name]
    return facts

Step 3 · Decide (AI)

Cell 15 · decide
# DECIDE: the AI reads the facts and may suggest ONE order
def decide(question, facts):
    reply = ask(f"""You help the purchase team. Use ONLY these facts: {facts}
Question: {question}
Tip: order enough jars for about 30 days. Choose the cheapest supplier.
Reply JSON only: {{"answer": "...", "supplier": "...", "quantity": 0}}""")
    return to_dict(reply)

Step 4 · Check (code)

Cell 16 · company rules
# CHECK: our code does the maths again and applies the company rules.
# It never trusts the AI's numbers.
def check(decision):
    supplier = SUPPLIERS.get(decision.get("supplier"))
    if supplier is None:
        return "FAIL", "unknown supplier"

    quantity   = int(decision["quantity"])
    days_left  = JAR["stock"] / JAR["daily_use"]                # how long stock lasts now
    days_after = (JAR["stock"] + quantity) / JAR["daily_use"]   # ...and after the order
    cost       = quantity * supplier["price"]                    # price comes from OUR data

    if supplier["days_to_deliver"] > days_left:
        return "FAIL", "the order arrives after our stock runs out"
    if days_after < 15:
        return "FAIL", "still less than 15 days of stock"
    if cost > 250000:
        return "NEEDS MANAGER", f"big order: Rs {cost}"
    return "PASS", f"stock will last {days_after} days, cost Rs {cost}"

Step 5 · Approve (person), only once

Cell 17 · approve and run everything
saved = set()      # remembers which decisions were already saved

# APPROVE: a person says yes. The same decision is never saved twice.
def approve(decision_id, status, role):
    if status == "FAIL":
        return "Not allowed: it breaks a rule."
    if status == "NEEDS MANAGER" and role != "manager":
        return "A manager must approve this."
    if decision_id in saved:
        return "Already saved. Nothing done again."
    saved.add(decision_id)
    return "Saved!"

# Run all the steps
question = "Should we reorder jars?"
needs = plan(question);              print("1 PLAN  :", needs)
facts = fetch(needs);                print("2 FETCH :", facts)
decision = decide(question, facts);  print("3 DECIDE:", decision)
status, reason = check(decision);    print("4 CHECK :", status, "-", reason)
print("5 APPROVE:", approve("DEC-1", status, role="analyst"))
print("  again  :", approve("DEC-1", status, role="analyst"))

  1. Plan: the AI said it needs the jar stock and the suppliers.

def measure_price_change(sql, v):
    rows = sql("SELECT price, unit_cost FROM products WHERE id = :id", id=v["product_id"])
    old, cost, new = rows[0]["price"], rows[0]["unit_cost"], v["new_price"]
    return {"margin":    round((new - cost) / new, 3),    # profit share of the new price
            "price_cut": round((old - new) / old, 3)}     # how much cheaper than before
    # (the real file returns a few more numbers too)

# FAIL     = never allowed, nobody can approve it

RULES = {

    "big_price_cut":   {"broken_if": lambda m: m["price_cut"] > 0.10,         "result": "APPROVAL", "why": "price cut above 10% needs a manager"},
    "min_cover":       {"broken_if": lambda m: m["days_of_stock_after"] < 15, "result": "FAIL",     "why": "less than 15 days of stock after the order"},
    "arrives_in_time": {"broken_if": lambda m: m["late_by_days"] > 0,         "result": "FAIL",     "why": "delivery arrives after our stock runs out"},
    "alternate_cost":  {"broken_if": lambda m: m["extra_cost"] > 0.08,        "result": "APPROVAL", "why": "more than 8% dearer than the usual supplier"},
    "large_order":     {"broken_if": lambda m: m["order_value"] > 250000,     "result": "APPROVAL", "why": "orders above Rs 2,50,000 need a manager"},

def build_vectors(docs):
    # 1. cut every document into pieces of about 300 letters
    pieces = [{"doc": d["name"], "text": p} for d in docs for p in cut_into_pieces(d["text"])]
    # 2. turn every piece into numbers with TF-IDF
    model = TfidfVectorizer(stop_words="english")
    vectors = model.fit_transform([p["text"] for p in pieces])
    return {"pieces": pieces, "model": model, "vectors": vectors}

def search(index, question, top=2, min_score=0.08):
    q = index["model"].transform([question])                  # question -> numbers
    scores = cosine_similarity(q, index["vectors"])[0]        # compare with every piece
    best = scores.argsort()[::-1][:top]                       # the 2 best matches
    return [... for i in best if scores[i] >= min_score]      # skip weak matches

def build_graph(db):
    graph = nx.DiGraph()
    for link, sql in company.GRAPH_LINKS:           # e.g. ("USES", "SELECT ... AS a, ... AS b")
        for row in run_sql(db, sql):
            graph.add_edge(row["a"], row["b"], link=link)   # one row = one arrow
    return graph

The whole decision agent in a few lines

agents.py · decision_agent (shortened)
def decision_agent(system, question):
    needs   = plan(system, question)                                    # 1. AI: what do I need?
    context = fetch(system, needs)                                      # 2. code: get it
    decision = decide(question, context)                                # 3. AI: what should we do?
    status, reasons, values, measures = check_action(system, decision)  # 4. code: maths + rules
    message = explain(question, context, decision, status, reasons, measures)   # 5. AI: simple reply
    # ... the result is saved with an id like "DEC-a3f9c1" so a person can approve it later (step 6)
1 · plan()

AI picks from menus

Shows the AI: the names of things (Jar = C-JAR), the question menu, graph names, document names. The AI replies: which database questions, which graph names, and which search words it needs.

2 · fetch()

Code gets the data

Runs only menu questions (anything else is skipped), searches the documents, and reads the graph arrows.

3 · decide()

AI answers + suggests

Gets the facts, the allowed actions, the rules and the guidance. Replies with an answer and at most one action.

4 · check_action()

Code checks

Checks the values, calls the measure function from company.py, and applies the rules.

5 · explain()

AI writes for people

Turns everything into a short, friendly message for the manager. No codes, no JSON.

6 · approve_and_write()

Person approves

Checks the result and the person's role, then saves the change only once.

Step 4 in code: the worst result wins

agents.py · check_rules (simplified)
def check_rules(measures, rule_names):
    # find every rule that is broken
    broken = [company.RULES[r] for r in rule_names if company.RULES[r]["broken_if"](measures)]

    if any(rule["result"] == "FAIL" for rule in broken):
        return "FAIL", ...             # one FAIL rule is enough to block it
    if broken:
        return "NEEDS MANAGER", ...    # only APPROVAL rules broken
    return "PASS", []                  # nothing broken
ResultMeaning
PASSFollows every rule. Anyone may approve.
NEEDS MANAGERAllowed, but only a manager may approve.
FAILBreaks a hard rule. Nobody can approve it.
CANNOT CHECKThe AI's values were wrong or missing, so we cannot check them.
NO ACTIONIt was just a question; nothing to change.

Step 6 in code: save only once

agents.py · approve_and_write (simplified)
def approve_and_write(system, decision_id, role):
    d = system["decisions"].get(decision_id)
    if d["status"] == "FAIL":                                  return "Sorry, this breaks a company rule."
    if d["status"] == "NEEDS MANAGER" and role != "manager":  return "This needs a manager's approval."

    with system["db"].begin() as c:     # all or nothing
        # write the decision id in the "diary". If it is already there, nothing is added.
        result = c.execute(..."INSERT INTO done_actions ... ON CONFLICT (key) DO NOTHING"...)
        if not result.rowcount:
            return "This was already saved earlier, so nothing was saved again."
        c.execute(...the action's SQL from company.py...)    # the ONLY place anything is changed
    return "Done! ... has been saved."

import os, json, re
from transformers import pipeline
import agents, main

os.environ["GEMINI_API_KEY"] = "not-used"   # main.py checks that a key exists

# A slightly bigger free model, because the project's prompts are longer
hf = pipeline("text-generation", model="Qwen/Qwen2.5-3B-Instruct",
              device_map="auto", torch_dtype="auto")

# Our own version of ask_ai: same input (a prompt), same output (a dictionary)
def ask_ai_local(prompt):
    messages = [{"role": "user", "content": prompt}]
    for attempt in range(3):                                        # try up to 3 times
        text = hf(messages, max_new_tokens=700, do_sample=False)[0]["generated_text"][-1]["content"]
        found = re.search(r"\{.*\}", text, re.S)                    # find the JSON part
        try:
            return json.loads(found.group(0))
        except Exception:
            messages.append({"role": "assistant", "content": text})
            messages.append({"role": "user", "content": "Reply with valid JSON only."})
    return {}

agents.ask_ai = ask_ai_local                 # the swap: one line!

system = main.start()
main.ask(system, "Should we reorder Jars?")
An important lessonA small model gives weaker plans and suggestions. But the system stays safe: bad values become CANNOT CHECK, and rule breaks become FAIL. A weaker brain makes the agent less helpful, not less safe, because the checking is done by code.

The whole day on one card

How to build an agent

1. Write down the goal.
2. Make a menu of what it may look up.
3. Make a short list of actions it may suggest.
4. Write the rules in code.
5. Decide who approves what.
6. Make sure nothing is saved twice.

Who does what

AI: understand, choose, suggest, explain.

Code: fetch data, do maths, check rules, save.

Person: say yes to anything important.
